# Project Memory

## Current State (v0.3.0)
- Layered domain architecture (`core/`, `data/`, `net/`, `ui/`, `l10n/`), `main.lua`
  as a thin orchestrator. 15 headless test suites, all green
  (`luajit tests/test_runner.lua`).
- **Testing status — be precise about this**: exercised against KOReader's official
  prebuilt Linux x86_64 binary running under Xvfb (a real KOReader runtime and
  widget framework, not headless mocks), which did catch several real bugs
  mock tests missed. This is **not** the same as testing on physical e-reader
  hardware (real touchscreen, real ARM SoC, real storage/battery constraints) —
  no physical device testing has happened. Versioned pre-1.0 and don't claim
  "tested on a real device" anywhere until that's actually true.
- Discovery via the `fusuyfusuy/awesome.koreader` catalog index (fast path) with
  a live GitHub search crawler as fallback; disk discovery and auto-linking for
  side-loaded plugins; live per-repo GitHub release checking on demand.
- Full plugin lifecycle: browse, install, update-check, manual-link/match,
  rollback, delete.
- Full patch lifecycle: browse patch-collection repos, drill into individual
  `.lua` files (indexed lazily per repo), install/update/delete into KOReader's
  real `patches/` directory with full tracking.
- Zip Slip / symlink containment on both the native-archiver and shell
  `unzip`/`tar` install paths. SQLite WAL cache with corruption auto-recovery.
  Side-by-side storage isolation from other package-manager plugins.
- Mirror/proxy support for restricted networks. Localized across 8 languages.

## Open Work
- **Async work**: install/refresh/update-check/README fetch each run one
  blocking HTTP or filesystem call on the UI thread; needs off-thread/
  subprocess execution so the UI doesn't freeze during these operations.

## Core Invariants & Architecture Rules
- **No Backward Compatibility Burden**: Strip obsolete hacks; maintain clean boundaries instead of complex polyfills.
- **Strict LuaJIT Local Budget**: Every module must strictly keep $\le 40$ top-level local variables to prevent LuaJIT register pressure on low-power e-readers.
- **Headless Testability**: Any new feature or bug fix must be runnable under `luajit tests/test_runner.lua` without requiring a full KOReader graphic build.
- **Non-Destructive Cache Guarantee**: Network dropouts, user cancellations, or rate limits must never wipe or corrupt existing SQLite cache data.
- **Zero UI Coupling in Pure Domain/Net**: `core/`, `data/`, and `net/` must never import `ui/` or `UIManager`.

## Domain Vocabulary & Gotchas
- **Zip Slip Path Traversal**: Always validate unpacked file paths with `realpath` and `isSubPath` before writing to disk. The `extractPlugin`/Archiver path validates entries before they touch disk; the shell `unzip`/`tar` fallback (`installPackage`) can't be pre-validated since an external process writes the files, so it is checked post-hoc with `StorifyInstaller.containExtractedTree()`, which also rejects any symlink found in the extracted tree outright (no realpath resolution available in Lua here, so symlinks aren't resolved-and-checked — they're just refused; see the `ponytail:` comment on that function for the upgrade path if legitimate symlink-containing packages ever appear).
- **SQLite WAL Mode & Auto-Recovery**: If SQLite header is corrupted, quarantine to `.corrupt.<timestamp>` and re-initialize schema without throwing uncaught exceptions.
- **SSRF & Token Leakage**: Always strip `Authorization` headers on redirect hops that leave `api.github.com`.
- **E-Ink Repaint Rate Limiting**: All progress animations must enforce a 1.5s repaint interval with `"fast"` monochrome waveforms to avoid screen ghosting.
- **`lfs.dir` Must Be Iterated In-Place**: Never do `local ok, iter_fn = pcall(lfs.dir, path)` and then call `iter_fn` standalone — KOReader's `libkoreader-lfs` generator closes over iteration state that only survives inside the original `for e in lfs.dir(path) do ... end` expression. Extracting the bare function and calling it later throws `bad argument #1 to '(for generator)'` on real devices even though it works fine against mock/stub `lfs` in headless tests. Always wrap the whole `for` loop in `pcall(function() ... end)` instead.
- **Headless Tests Can Miss Real-Device-Only Bugs**: Mock fidelity gaps mean a bug can pass all 15 headless suites and still break on real KOReader hardware (dialog widget params, iterator semantics, dead UI callbacks have all done this before). When a bug report cites an on-device stack trace, don't trust a green test suite alone — trace the real call path, and where possible verify live against a real KOReader install.
- **`_meta.lua`'s `name` Field Is Dead**: Real KOReader's `PluginLoader:_discover()` derives a plugin's identity purely from its folder name (`entry:sub(1, -10)`, stripping `.koplugin`) and explicitly discards + warns on any `name` key found in `_meta.lua`. Never add one back — use `fullname` for the display name.
- **awesome.koreader Catalog Has Non-Repo Entries**: The catalog's `plugins[]` includes `"type": "builtin_plugin"` rows for plugins bundled inside the `koreader/koreader` monorepo itself (keepalive, kosync, opds, etc.). Their `full_name`/`url` are a repo+subpath (`koreader/koreader/plugins/x.koplugin`), not a flat `owner/repo` — every other entry type (`plugin`, `community_plugin`, `patch`, `patch_collection`) is flat. `net/storify_crawler.lua`'s `fetchAwesomeCatalog` filters `builtin_plugin` out entirely before normalization; don't remove that filter without also fixing README/download URL building for repo+subpath entries AND deciding whether offering an already-bundled feature as "installable" even makes sense.
- **`Cache.listRepos()` Returns an Array, Not a Map**: It's a plain integer-indexed array of repo rows. `core/storify_matcher.lua`'s `findMatchingRepo`/`syncFromDisk` correctly iterate it as an array. But `ui/storify_updates_dialog.lua`'s `UpdatesModel.prepareUpdateCandidates(installed, patches, remote_metadata, ignored)` looks remote info up by string key (`remote_metadata.repos[repo_key]`) — passing the raw array straight through makes every lookup silently return `nil` (`array[string]` is always nil). `main.lua`'s `showUpdates()` calls a local `buildRepoMap(repos)` helper to index the array by `full_name`/`name` before passing it in — any new caller of `prepareUpdateCandidates` must do the same.
- **Installed-Plugin Records Need `repo_owner`/`repo_name`/`repo_full_name`, Not Just `repo`**: `prepareUpdateCandidates` computes its lookup key from `plugin.repo_full_name or (plugin.repo_owner and plugin.repo_name and ...)` — it never reads the generic `repo` string field. Any code path that records an install (`handleInstallRequest`, `handleManualLink`, `syncFromDisk`) must write all three fields, or the plugin is permanently unmatchable even with a correct `repo` string. `syncFromDisk`'s reconciliation only re-derives these fields when `repo_full_name`, `repo`, AND `repo_name` are *all* missing — a lone `repo` string blocks that fallback from ever kicking in. Always write the full field set `handleManualLink` in `main.lua` uses as the reference shape.
- **`nil == nil` Is a Common Ignored-Version Trap**: version-comparison/ignore checks that do `ignored_versions[key] == latest_ver` must guard `latest_ver` truthy first — when neither side has a value (e.g. the catalog has no version info for this repo, the common case), `nil == nil` evaluates true and silently misroutes the item into the wrong status branch.
- **Toolbars Must Measure, Never Assume, Screen Width**: A `HorizontalGroup` of `Button`s with no wrapping will silently render past the screen edge on a narrower real device even though it looks fine in whatever window the code was last eyeballed in. The fix pattern: measure each child via `getSize().w` and greedily pack into fixed-width rows (`UpdatesModel.packButtonsIntoRows` in `ui/storify_updates_dialog.lua`), folding whatever doesn't fit behind an overflow "More" button/menu rather than trusting a fixed button count to fit. The headless test stubs mock every widget's `getSize()` at a flat 800px regardless of content (see `tests/stubs/koreader_stubs.lua`'s `mock_widget_container`), so packing/wrapping logic needs deterministic fake-width unit tests (fake objects with a controlled `getSize()`) to be meaningfully tested at all.
- **`patch_files` Rows Are Keyed by `repo_id`, Not Owner/Name**: `Cache.listPatchFiles(repo_id)`/`listPatchFilesByRepo()` only carry `path`/`filename`/`sha`/`download_url`, not which repo they belong to by name — join against `Cache.listRepos("patch")`'s `.repo_id` field to get `owner`/`name`, then build the `"owner/repo:path"` key `UpdatesModel.prepareUpdateCandidates`'s patch branch looks up (see `buildPatchesMap()` in `main.lua`).
- **A Passive Reconciliation Pass and an Explicit Retry Button Are Different Guarantees**: `syncFromDisk` already re-attempts `Matcher.findMatchingRepo` automatically on every dialog open, but only when an installed record has *no* repo info at all — a stale bare `repo` string blocks it forever. The "Match with repo" toolbar button (`Storify:handleMatchWithRepo` in `main.lua`) exists specifically to bypass that staleness guard and retry unconditionally for anything currently showing `status == "unlinked"`.
- **Session-Only State on `self` Is a Legitimate Alternative to Schema Changes**: `Storify:handleCheckAllUpdates`'s fetched release tags live only in `self._checked_releases` (an in-memory table on the running plugin instance), merged into the repo lookup on every `showUpdates()` call, and reset on app restart. This avoids a schema change to the `repos` cache table for what's fundamentally an on-demand action, and correctly models "checked this session" rather than a permanent fact. Prefer this pattern for other on-demand/explicit-refresh data before reaching for a schema change.
- **`StorifyProgress` Constructs Fine Under the Headless Widget Mocks**: `ui/widget/progresswidget`/`ui/gesturerange`/`ui/time` are all `pcall`-wrapped with safe fallbacks in `ui/storify_progress.lua` itself, and `Device`/`Size` field lookups there are all `and/or`-guarded — so `StorifyProgress:new{...}:show()` works under `tests/stubs/koreader_stubs.lua`'s generic `mock_widget_container` even though nothing stubs `ui/storify_progress` directly.
- **A Patch Is One File in `DataStorage:getPatchesDir()`, Not a Zip Install**: KOReader's real `userpatch.lua` runs every `.lua` file directly out of that flat directory (no subfolders), alphanatural-sorted, filtered by a `^<priority>%d*-` filename prefix (e.g. `2-foo.lua`) — see `userpatch.lua` in the KOReader frontend. Never route a patch through `Installer.installPackage` (that's for `.koplugin` zip archives into `plugins/`); download the single file with `Net.requestToFile` straight to `DataStorage:getPatchesDir() .. "/" .. filename`, preserving the filename exactly as indexed.
- **Patch File Trees Are Indexed Lazily, Per-Repo, On First Browse** — Not Eagerly For The Whole Catalog: `Crawler.fetchPatchFileTree(repo)` does one `GitHub.fetchRepoTree` call and populates `Cache.storePatchFiles` for a single patch-collection repo. `Crawler.refreshCatalog`'s normal awesome.koreader fast path *never* calls this for any repo — running it eagerly for all ~100+ patch-collection repos on every "Refresh Catalog" would reintroduce exactly the crawling cost/lag that catalog replaced. `Storify:showPatchFileBrowser` in `main.lua` calls it on-demand, the first time a user opens a given repo's file list; `Cache.listPatchFiles(repo.repo_id)` is checked first so a repo already visited this session doesn't refetch.
- **`Crawler.fetchPatchFileTree`/`repo` Accepts Two Different Shapes**: a raw GitHub search API object (`.id`, `.owner` as a `{login=...}` table, `.default_branch` top-level) *or* a `Cache.listRepos()` row (`.repo_id`, `.owner` as a plain string, `.default_branch` only reachable via the lazily-loaded `.data` blob). The function normalizes both — don't assume one shape when adding a new caller.
- **`README.md` Is the Doc That Must Stay Current**: check it against real file/line/test counts when touching architecture. There is no `architecture-report.md`/`phased-development-plan.md`/`index.html` anymore (removed as stale/orphaned artifacts) — README is the single source of truth for project docs.
